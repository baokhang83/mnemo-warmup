Annotations and CLI reference

Every warmup.mnemo.io/* annotation with its default, and every command and flag. Set annotations on the Deployment’s pod template (spec.template.metadata.annotations) as quoted strings.

Three annotations are required today: enabled, store and exit-mode. The injector stops with missing warmup.mnemo.io/exit-mode otherwise.

Annotations

AnnotationRequiredDefaultMeaning
warmup.mnemo.io/enabledyes—"true" turns adoption on. "false" (or no annotations) leaves the workload untouched and restores fields the injector owns.
warmup.mnemo.io/storeyes—Archive repository, oci://host[:port]/path. Not your application image repository.
warmup.mnemo.io/exit-modeyes—How the trainer knows startup is done: spring-refresh or http-probe.
warmup.mnemo.io/probe-urlwith http-probe—HTTP URL reachable from the trainer pod. Not allowed with spring-refresh.
warmup.mnemo.io/containermulti-container pods—Name of the application container.
warmup.mnemo.io/commandnofrom command + argsComplete JSON string array for the launch when the Java command comes from ENTRYPOINT, e.g. ["java","-jar","/app/app.jar"].
warmup.mnemo.io/pull-secretnoanonymouskubernetes.io/dockerconfigjson Secret with pull access to the archive repository.
warmup.mnemo.io/push-secretnoanonymousThe same with push access, used by the trainer.
warmup.mnemo.io/plain-httpnofalse"true" talks plain HTTP to the registry. Local registries and tests only.
warmup.mnemo.io/tools-deliverynoinit-containerinit-container or image-volume (Kubernetes 1.33+, supporting runtime). A pull Secret or node cache keeps a fetch init container.
warmup.mnemo.io/node-cache-urlwith node cache—HTTPS origin of the node-local cache Service.
warmup.mnemo.io/node-cache-ca-configmapwith node cache—ConfigMap with the cache CA certificate under ca.crt.
warmup.mnemo.io/node-cache-audiencewith node cache—Audience for the projected service-account token.

Commands

CommandWhat it doesOptions (defaults)
buildTrain an archive locally and write it with a manifest.--jar, --java-home, --cache-type auto|appcds|aot, --exit-mode spring-refresh|http-probe, --url, --warmup-url, --warmup-script, --poll-interval-millis 500, --timeout-seconds 300, --jvm-arg, --image-digest, --work-dir .mnemo-warmup
benchCompare start with no archive, AppCDS and (JDK 25+) AOT in fresh JVMs.build options plus --runs 3, --warmups 1
pushUpload archive and manifest, tag fp-<hex>.--store, --registry-auth, --plain-http
fetchLook up, verify (digest) and write the archive for this exact launch. Exits 0 on any problem unless --strict.--jar, --jvm-arg, --image-digest, --store, --registry-auth, --plain-http, --out .mnemo-warmup/cache, --cache-type, --store-timeout-seconds 120, --strict
runPrint the final launch command with the archive flag if it fits.--cache-dir, --image-digest, --print, --format shell|nul, --spawn, --stop-timeout-seconds 25
injectRewrite a rendered YAML stream offline (stdin to stdout). No cluster contact.--namespace, --preview, --tools-image

Exit codes for build: 0 success, 1 training failed, 2 invalid input. push: 0 success, 1 store failure, 2 invalid input. fetch exits 0 by default, whatever goes wrong; --strict exits 1 on a store problem and 2 on bad arguments.

Fixed in this release

  • Trainer CronJob: every 10 minutes, concurrencyPolicy: Forbid, one-hour deadline. Not configurable per workload yet.
  • Only Deployment workloads; launches with -cp and a main class and @argfiles are refused.
  • Deployment names over 63 characters are rejected (the name is used as a label value).
